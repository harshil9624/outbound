# Outbound

An Android-first arrow puzzle game. Every arrow is one continuous path with bends and a single head. Tap an arrow and it slides off the board, but only if the lane in front of its head is clear. Clear the board without running out of hearts.

> **Easy to understand the arrow. Hard to decide the correct move.** (from [LEVEL_DESIGN_BIBLE.md](LEVEL_DESIGN_BIBLE.md))

## Overview

Outbound is a casual, offline mobile puzzle game built with Expo and React Native, aimed at players who like short, thoughtful puzzle sessions.

- **What it is:** a tap-away puzzle. Each level is a grid of colourful, animal-headed arrows that block each other. The player has to work out the order in which arrows can leave.
- **Main purpose:** a readable puzzle with real decisions. Arrows are easy to read (body, head and direction are always clear), but choosing the right move takes thought.
- **How it plays:**
  - A blocked tap costs a heart (3 per level).
  - Clearing a level earns 1–3 stars and coins.
  - Coins buy boosts.
  - Progress, coins, stars, streak and settings are saved on the device.
- **No backend:** everything runs locally. Levels ship with the app, and player data is stored with MMKV.

## Features

- **Arrow puzzle engine:** pure TypeScript logic for moves, blocking, win and loss, hints, hammer and extra lives, with no React dependency.
- **70 levels:** levels 1–8 are handcrafted. Levels 9–70 come from a deterministic generator (`scripts/generateLevels.ts`), and the arrow count and board size grow from chapter to chapter.
- **Journey map:** a scrolling, chapter-based level map with 8 chapters of 14 levels each, plus challenge and master levels. Animations show stars earned, newly unlocked levels and the player's mascot moving along the route.
- **Animated board:** arrows are drawn with SVG and have animal faces whose expressions react (happy, scared, ouch). Arrows slide out along their own path, nudge when blocked, and flash the arrow blocking them.
- **Hearts with moods:** 3 lives per level, shown as animated hearts that change expression as lives run out.
- **Coin-priced boosts:**
  - **Hint** (15 coins): highlights a safe move.
  - **Hammer** (40 coins): removes any arrow, with a flying-hammer animation.
  - **+1 Heart** (30 coins): adds a life and can revive a lost level.
  - **Restart:** free.
- **Stars and rewards:** 1–3 stars based on mistakes, hints and hammers used. Coins come from difficulty, stars and a first-clear bonus.
- **Win screen:** a dropping card, stars, coin count-up, fireworks, confetti and a sunburst.
- **Daily streak:** current and best streak, a monthly play calendar, and milestone rewards at 3, 7, 14, 30, 60 and 100 days.
- **Home screen:** a greeting with the player's avatar, a Continue card with a board thumbnail, and shortcuts to the Journey and Streak screens.
- **Settings:**
  - Editable player name and animal avatar.
  - Sound, vibration and reduced motion toggles.
  - How to play.
  - Reset progress, with confirmation.
  - In development builds only, buttons to add test coins.
- **Sound effects:** short WAV effects generated by a script (`scripts/generateSounds.ts`) and played with `expo-audio`.
- **Local saving:** player progress and settings are kept in MMKV through Zustand's `persist` middleware.

## Architecture

The full design notes are in [ARCHITECTURE.md](ARCHITECTURE.md). Level design rules are in [LEVEL_DESIGN_BIBLE.md](LEVEL_DESIGN_BIBLE.md).

The code is in layers. Game rules don't depend on React, and screens don't contain rules.

- **Pure core** (`src/game`, `src/types`, `src/constants`): plain TypeScript with no React or native imports, covered by unit tests.
  - `engine/`: the core rules: tapping an arrow, exit checks, win check, hints, the hammer, extra lives, stars and rewards. Every function is pure and returns new state.
  - `layout/`: board pixel layout, arrow drawing geometry and tap hit-testing.
  - `levels/`: handcrafted levels, `generated.ts`, and the `levelProvider` that is the only way the app loads levels.
  - `generation/`, `analysis/`, `validation/`: the level generator, difficulty metrics and solvability checks (used by scripts and tests).
  - `journey/`: chapter definitions, map layout and progress mapping for the Journey map.
  - `progression/`: streak and calendar logic.
  - `session/`: builds the result of a finished level.
- **State** (`src/store`, Zustand):
  - `gameStore`: the current level session, kept in memory only.
  - `playerStore`: coins, progress, stars, streak and profile. Saved to MMKV, with versioned migrations.
  - `settingsStore`: sound, vibration and reduced motion. Saved to MMKV.
  - `boostActions`: coin-priced boost logic that combines the game and player stores.
- **Storage** (`src/storage`): `mmkv.ts` is the only file that imports MMKV. `zustandStorage.ts` adapts it to Zustand's `persist` middleware; reads are synchronous, so stores are ready on first render.
- **Screens and routes** (`src/app`, Expo Router):
  - `index.tsx`: the splash screen.
  - `(tabs)/`: Home, Journey, Streak and Settings, with a custom bottom navigation bar.
  - `level/[levelId].tsx`: the game screen.
  - `win/index.tsx`: the win screen.
- **Hooks** (`src/hooks`): `useLevelSession` connects stores, engine, sounds and progression for one level. `useJourney` turns progress into map data.
- **Components** (`src/components`): `game/` (board, arrows, faces, hearts, boosts, hammer), `journey/` (map zones, tiles, thumbnails), `win/` (celebration effects), `nav/`, `icons/`, and `ui/` (shared hard-shadow buttons and cards).
- **Theme and utilities:** `src/theme` holds colour, typography and spacing tokens. `src/utils` has date, colour, math and haptics helpers. `src/audio` handles sound loading and playback.
- **Android native layer:** `android/` is generated by Expo (`expo run:android`) and is **git-ignored**. Native settings come from `app.json` and the installed packages.

## Installation

```powershell
git clone https://github.com/harshil9624/outbound.git
cd outbound
bun i
```

Outbound uses native modules (MMKV), so it **cannot run in Expo Go**. You need the development build described below.

## Running the App (Development)

Connect an Android device with USB debugging on, or start an emulator, and then:

```powershell
bun run android   # first time: generates android/, builds and installs the dev client, starts Metro
bun run dev       # afterwards: starts Metro for the installed dev client
```

Run `bun run android` again whenever a native dependency or a native setting in `app.json` changes. For JavaScript and TypeScript changes, `bun run dev` is enough. If Metro serves stale code, clear its cache:

```powershell
bun run dev -- --clear
```

## Building for Android

First check the machine (JDK 17, SDK parts, adb and a connected device):

```powershell
bun run android:doctor
```

`android/` is generated from `app.json` and is git-ignored. Create or refresh it with prebuild; this keeps the existing folder and does not delete it:

```powershell
bun run android:prebuild
```

### Local builds on Windows (Gradle)

| Command | Output |
|---|---|
| `bun run android:apk` | Release APK: `android\app\build\outputs\apk\release\app-release.apk` |
| `bun run android:apk:debug` | Debug APK: `android\app\build\outputs\apk\debug\app-debug.apk` |
| `bun run android:aab` | Release bundle for Google Play: `android\app\build\outputs\bundle\release\app-release.aab` |
| `bun run android:release:device` | Builds a release build and installs and launches it on the connected phone |
| `bun run android:clean` | Gradle clean |

To install a built APK on the connected phone:

```powershell
adb install -r android\app\build\outputs\apk\release\app-release.apk
```

Judge performance on a **release** build; development builds are much slower.

> **JDK:** Gradle uses `JAVA_HOME`, which must be JDK 17. Android Studio's bundled JDK (25) does not work: Gradle 8.14.3 cannot run on Java 25. If you open `android/` in Android Studio, set *Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK* to `JAVA_HOME`.

### EAS builds

`eas.json` defines three Android profiles:

| Profile | Output | Use |
|---|---|---|
| `development` | Debug APK with the dev client | Internal testing with Metro |
| `preview` | Release APK, internal distribution | Testing on real phones |
| `production` | App bundle (`.aab`) | Google Play |

`appVersionSource` is `local`, so the version comes from `app.json` (`version` and `android.versionCode`). Increase `android.versionCode` for every Play Store upload.

- **EAS local builds (`eas build --local`) do not run on Windows.** EAS CLI only supports local Android builds on macOS or Linux. On this Windows machine, use the Gradle scripts above, which run the same Gradle build. To use `eas build --local`, run it inside WSL2 with a Linux JDK 17 and Android SDK.
- **EAS cloud builds** work from Windows: `bun run eas:preview` or `bun run eas:production`. The first run asks you to log in to Expo and link the project, which adds a project ID to `app.json`.

> **Release signing is not set up yet.** The generated `android/app/build.gradle` signs release builds with the **debug keystore**. That works for local testing, but such builds cannot be uploaded to Google Play. A release keystore (or EAS Build) still has to be configured.

## Levels

- Levels 1–8 are handcrafted in `src/game/levels/level01.ts` to `level08.ts`.
- Levels 9–70 are generated. To change them, edit the chapter plans in `scripts/generateLevels.ts`, then run `bun run generate-levels`. Don't edit `generated.ts` by hand.
- After any level change, run `bun run validate-levels` and `bun run test`.
- Design rules and the difficulty model are in [LEVEL_DESIGN_BIBLE.md](LEVEL_DESIGN_BIBLE.md).

## Troubleshooting

| Problem | Fix |
|---|---|
| The app opens in Expo Go and crashes, or MMKV errors appear | Use the dev build: run `bun run android`, not Expo Go |
| The Gradle build fails with a Java version error | Make sure `java -version` reports 17 and `JAVA_HOME` points to JDK 17 |
| `SDK location not found` | Set `ANDROID_HOME`, or create `android\local.properties` with `sdk.dir=C:\\Users\\<you>\\AppData\\Local\\Android\\Sdk` |
| Metro shows old code or "unable to resolve" errors after a change | `bun run dev -- --clear` |
| A native module was added or `app.json` changed | Rebuild with `bun run android` |
| `adb` is not found | Add `%ANDROID_HOME%\platform-tools` to `PATH` |
